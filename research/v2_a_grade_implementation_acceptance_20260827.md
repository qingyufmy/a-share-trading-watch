# V2 策略系统 A 级迭代实施验收

- 验收范围：项目源码、V2 策略门控、模拟盘执行合约、逐股生命周期、飞书整点卡、盘前质检与发布一致性
- 当前结论：**源码实现验收通过；运行目录尚未部署，不能宣称线上已达到 A 级。**

## 一、已完成的核心修复

1. **行情证券身份唯一化**
   - 腾讯 `sh000001`、`sz399001`、`sz399006` 使用带交易所的唯一键。
   - `sz000001` 平安银行不再覆盖 `sh000001` 上证指数。
   - 实时抽样结果：平安银行 `-1.19%`，上证 `+1.13%`，深成 `+1.50%`，创业板 `+1.71%`；市场状态正确识别为 `growth_lead`。

2. **开盘退出成熟度门控**
   - 结构硬失效、Gap Failure、Distribution Shock 仍可即时退出。
   - REDUCE、TAKE_PROFIT 等软退出至少等待 09:35、1 根当日已收盘 5m 和 1 根当日已收盘 15m。
   - 09:30 无当日闭合 K 线时只进入 `NO_ADD`，避免历史 15m 结构误触发开盘卖出。

3. **E6 修复环境升级路线**
   - 只接受 120m `REPAIR`，不放行 `BEAR/UNKNOWN`。
   - 要求市场处于 growth_lead、broad_strong、recovery 或 rotation。
   - 要求板块持续、龙头健康、15m 首次健康回踩后再收复、5m 连续站稳 VWAP、抬高低点、量能、位置、Room/RR 全部通过。
   - E6 使用 `0.20` 试仓倍率，独立于 E1-E5，不通过条件时仍为 WAIT。

4. **动态轮动风险预算**
   - risk_off、transition、rotation_defensive、data_stale 时预算归零。
   - growth_lead、broad_strong 时可将轮动单标的上限由基础值动态提高，但硬上限为 `2.5%`，单次试仓不超过 `1%`。
   - recovery、rotation 仅小幅提高；黄色风险折减 33%；全市场红色风险归零。

5. **逐股生命周期与再入场审计**
   - 新增 `TRIGGERED_BUT_MISSED`，记录 14:45 后已完成但因时段错过的触发。
   - 新增 `MANAGING_REENTRY`，区分普通持仓管理和修复/再入场管理。
   - 同一股票按交易日和证券代码保持唯一 track，不再因 scenario 变化重启为 IDLE。
   - E6 对盘前持仓保护标的只在“当前确有可卖底仓 + 完整仓位计划”时授权计划内做 T/再入场；空仓仍服从盘前禁止新增。

6. **飞书与调度隔离**
   - 整点卡先做 delivery key 去重，再判断测试禁推送。
   - launchd 明确允许推送时会清除父进程继承的 `A_SHARE_SKIP_FEISHU`。
   - 飞书漏斗新增“触发但错过”和“持仓修复/再入场管理”中文状态。

7. **发布漂移阻断**
   - 安装器生成 SHA-256 `release_manifest.json`，包含核心 Python、配置和工作台静态文件。
   - 盘前质检逐文件核对清单；缺失或漂移会阻止新增模拟买入，但不隐藏结构硬退出。

## 四、上线后的 A 级验收门槛

1. 盘前质检显示发布清单一致，实时引擎、计划源、仓位计划和数据库均通过。
2. 连续 3 个交易日不再出现指数身份错配、09:30 软退出、生命周期从 IDLE 重启或飞书重复整点卡。
3. 每只重点股票至少形成 DISCOVERED、SETUP_FORMING、NEAR_TRIGGER、TRIGGERED/EXPIRED 中可解释的真实路径。
4. 零交易日必须能给出逐股剩余门槛；触发后未成交必须记录 UNFILLED 或 TRIGGERED_BUT_MISSED。
5. E6 只能在完整修复链成立时触发；不得通过单纯放宽 BEAR、VWAP、量能、Room/RR 或时段门控提高交易数。
6. 模拟盘订单必须由冻结执行合约生成，成本后 RR 不低于 1.50，且仓位不超过盘前计划或动态试错预算。
